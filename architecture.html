The Copilot is a multi-layer, agentic system that bridges natural language problem descriptions with quantum circuit execution on IBM Quantum hardware or local simulators. A user types a plain-English optimization problem; an LLM agent (Claude) parses it, a QUBO formulator converts it to a Hamiltonian, a QAOA circuit is built and transpiled, a classical COBYLA optimizer tunes the variational parameters via the MCP Estimator tool, and finally the best bitstring solution is decoded and presented with visualizations.

Layer 1 — Intelligence
LangGraph + Claude LLM
Orchestrates the pipeline as a stateful directed graph. Claude parses NL problems and summarises results.

Layer 2 — Tool Interface
MCP Server + Client
Standardised interface between the AI agent and Qiskit. Exposes 4 tools: sampler, estimator, backend-list, validator.
MCP SDK stdio transport
Layer 3 — Quantum
Qiskit + IBM Quantum
QAOA ansatz generation, transpilation, Sampler/Estimator primitives. Runs on AerSimulator or IBM QPU.

The 5 Processing Modules
Module 1 Problem Intake & Reasoning Agent
modules/intake_agent.py

Uses Claude LLM to parse a natural language problem into a structured JSON object containing decision variables, objective function, and constraints.

  • Sends user input + system prompt to claude-opus-4-6
  • Extracts assets, objective direction, weights
  • Separates hard vs soft constraints
  • Returns clarification_needed=True if problem is under-defined
  • Graph routes to END if clarification is needed
Module 2 Automated QUBO Formulator
modules/qubo_formulator.py

Converts the parsed problem into a mathematical Quadratic Unconstrained Binary Optimization model, then maps it to a quantum Ising Hamiltonian.

  • Builds qiskit_optimization.QuadraticProgram
  • Adds binary variables (one per asset)
  • Encodes cardinality + budget constraints
  • Runs QuadraticProgramToQubo (slack variables)
  • Calls to_ising() → SparsePauliOp
  • Extracts QUBO Q-matrix for visualization
Module 3 Quantum Circuit Constructor
modules/circuit_constructor.py

Builds the QAOA parameterised ansatz from the Ising Hamiltonian and validates it against the target hardware via transpilation.

  • Chooses QAOA layers p: 2 (n≤5), 1 (n≤10), 1 (n>10)
  • Instantiates QAOAAnsatz(cost_operator=H, reps=p)
  • Runs generate_preset_pass_manager(level=1)
  • Checks qubit count ≤ backend capacity
  • Checks transpiled depth ≤ 200 (coherence limit)
  • Serialises to OpenQASM 3 for MCP transport
Module 4 Hybrid Execution Manager via MCP
modules/execution_manager.py

The heart of the system — runs the classical-quantum hybrid optimisation loop using COBYLA and MCP tool calls.

  • Serialises Hamiltonian to JSON for MCP transport
  • Initialises random γ/β parameters in [0, π]
  • COBYLA calls MCP Estimator each iteration
  • On IBM failure → auto-fallback to AerSimulator
  • After convergence: calls MCP Sampler for bitstrings
  • Saves full experiment log (params, energy history) to logs/
Module 5 Results Analyzer & Visualizer
modules/results_analyzer.py

Decodes raw quantum measurement bitstrings into human-readable asset selections, validates constraints, and generates visualisations.

  • Decodes bitstrings: rightmost bit = q₀ = first asset
  • Checks hard constraint satisfaction per candidate
  • Selects best feasible solution by objective value
  • Brute-force classical optimum (n ≤ 20) for Approx. Ratio
  • Approx. Ratio = quantum_obj / classical_optimum
Outputs
  • Selected assets + objective value
  • Constraint satisfaction flag (✅ / ❌)
  • Approximation ratio vs classical optimum
  • Matplotlib histogram: top-10 bitstring probabilities
  • Matplotlib convergence curve: energy vs COBYLA iteration
  • Top-5 candidate solutions table

Parameter Encoding
For p QAOA layers, the parameter vector is:
[γ₁, β₁, γ₂, β₂, …, γₚ, βₚ]
γ (gamma) controls the cost Hamiltonian rotation.
β (beta) controls the mixer Hamiltonian rotation.
🛡️
Error Handling & Fallback Strategy
IBM Quantum failure
Any RuntimeError from IBM primitives during COBYLA iteration
→ Auto-switch to AerSimulator, retry same iteration
Qubit overflow
Problem requires more qubits than the target backend supports
→ transpilation_feasible=False, error set, user notified
Depth exceeded
Transpiled circuit depth > 200 gates (coherence budget)
→ Warning logged, execution continues with flag
Clarification needed
LLM cannot extract sufficient information from user input
→ Graph routes to END, clarification question surfaced
General node failure
Any exception in any node sets state['error']
→ handle_error node, retry_count++, max 2 retries
No feasible solution
All top bitstrings violate hard constraints
→ Return highest-probability candidate with warning
